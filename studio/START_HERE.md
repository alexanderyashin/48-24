# Как начать работу

Главная единица работы — небольшая задача с понятным результатом и владельцем. Студийная структура обслуживает работу двух авторов; она не требует заполнять все папки до первой сцены.

## Саша или Иван начинает задачу

1. Откройте Issue по форме «Рабочая задача». Укажите задачу, себя, затронутые пути и критерий готовности. Если работаете без Issue, запишите те же сведения в описании PR.
2. Убедитесь, что другой автор не меняет тот же файл. Откройте свежую ветку от main, например `work/ivan/ural-station`.
3. Возьмите карточку из [templates](../templates/README.md) и сохраните в нужной области `drafts`. Не создавайте постоянные папки «Саша», «Ваня», «Новая версия», «final-final».
4. Разрабатывайте черновик сами или с ИИ. В обоих случаях у материала есть ответственный человек, источник и отметка об использовании ИИ.
5. Откройте PR, приложите результат проверки и сформулируйте вопрос к соавтору. Принятый в main черновик остаётся черновиком.

Для проверки достаточно Python 3.11+ и Git. Самая простая команда из корня: `python tools/validate_repo.py`. Для работы с Git можно использовать GitHub Desktop, VS Code или веб-интерфейс GitHub; ветки и PR нужны во всех вариантах.

## Что передать нейросети

«Прочитай AGENTS.md и README выбранного раздела. Задача: … Работай в ветке … Только пути … Основания: … Результат: … Не закрывай открытые вопросы выдуманным согласованием. В конце передай diff, проверку и незакрытые вопросы».

## Что решить в ближайшее время

- Подтвердить GitHub-логин Ивана и добавить ему доступ; локальная запись в team.json не предоставляет доступ к GitHub.
- Включить защиту main из [пакета rollout](rollout/README.md) после первой успешной проверки.
- Вдвоём проверить перенос SPOT и утвердить первую небольшую порцию канона.
- Выбрать первую самостоятельную историю/пробный выпуск. Игра, книга, видео и настолка имеют место в структуре, но не объявлены одновременно запущенными производствами.
