# Работа с изображениями шрифтами аудио и исходниками

Каждый ресурс должен иметь понятные происхождение, владельца, статус и связь с историей или продуктом. Имя файла и красивая картинка не заменяют эти сведения.

## Где хранить

Небольшие согласованные превью, SVG, тексты, палитры и метаданные можно хранить в Git. Локальный предел проверки для одного бинарного файла — 20 MiB; это наше организационное ограничение, а не лимит GitHub. Видеомастера, многослойные проекты, стемы, большие 3D-сцены и сборки хранятся во внешнем согласованном хранилище; в Git остаются README, паспорт, ссылка и SHA-256.

Git LFS пока не включён: владелец хранилища, квота и порядок доступа не выбраны. `.gitattributes` сейчас настраивает текстовые окончания строк и бинарные типы. Нельзя обещать, что одного этого файла достаточно для хранения гигабайтных исходников. Подключение LFS/внешнего хранилища — отдельное производственное решение.

## Паспорт ресурса

Рядом с каждым загруженным бинарным ресурсом сохраните `<filename>.<ext>.asset.json` по [шаблону](../templates/asset.example.json). Обязательны ID, название, версия/статус, человек-ответственный, источник, правообладатель, разрешение/лицензия, AI provenance, дата и хеш фактического файла. Канонический ресурс требует решения авторов; отвергнутый — причины и связи с заменой.

Для внешнего мастера заполните [реестр ресурсов](registers/asset-register.csv) и карточку Markdown: что это, доступная участникам ссылка, хеш, размер, формат, версия, права, связь с превью. Не коммитьте фиктивные LFS pointers или пустые файлы вместо оригинала. Недоступный мастер обозначается недоступным, а не готовым.

Принятые значения clearance для опубликованного бинарного файла: `project-authorized`, `permission-on-file`, `public-domain`, `licensed`. Они выбираются только на основании действительных прав. При `pending` храните описание вопроса/ссылку; сам неразрешённый файл не загружайте. Проверка JSON не устанавливает истинность заявленного разрешения.

## Исходники и производные

Различайте мастер и превью. Экспорт содержит ссылку `derived_from` на ресурс-источник; разрешение исходника не расширяется при конвертации. Один бинарный мастер имеет одного текущего редактора. Конкурирующие художественные варианты получают разные ID, а не одновременно перезаписывают один файл.

Для цвета укажите цветовое пространство (например sRGB), HEX и предназначение. Для печати CMYK/профиль согласуются с производством; автоматический перевод HEX не считается проверенным печатным цветом.

Для шрифта проверьте отдельно право на передачу файла, использование в печати, web embedding, встраивание в игру и модификацию. В реестре должны быть версия лицензии и ссылка. Для голосов и музыкальных записей нужны права не только на текст/композицию, но и на использованные записи и исполнение; в публичном паспорте достаточно безопасной ссылки на подтверждение.
