## Где искать и где редактировать

1. Для темы откройте предметную страницу вики; для известного ID используйте поиск по репозиторию или реестр соответствующего типа.
2. Перейдите в профильный документ. Вики — указатель, содержание редактируется в разделе мира, повествования, искусства или производства.
3. Прочтите статус конкретного абзаца. Один документ может содержать и исходный консенсус, и дискуссию, и пробел.
4. Если меняется смысл, обновите обе языковые версии и связанные вопросы. Новое художественное решение проходит отдельное согласование.
5. Проверьте запись каждого изменённого/добавленного файла в каталоге и ссылки из двух вики.

## Как читать метки

`Draft` относится к рабочей редакции. `КОНСЕНСУС` означает согласие с конкретной формулировкой в исходнике. `РАМКА САШИ`, предложения, совместная разработка и редакционные рекомендации относятся к обсуждению. `БЕЛОЕ ПЯТНО` обозначает отсутствие решения. Ранние и отменённые версии вынесены в историю вариантов.

Ни английский перевод, ни каталогизация, ни слияние ветки не утверждают канон. Все переводы этой миграции имеют статус `draft-unreviewed`: выполнены полностью, но человеческая приёмка не подменяется технической проверкой.

## Идентификаторы

| Префикс | Значение |
| --- | --- |
| CAN | Исходное положение с точным авторским статусом |
| DIV | Развилка для консолидации вариантов |
| GAP | Недостающее решение или исследование |
| CHAR | Персонаж или персонажная функция |
| ARC | Сюжетная линия, арка или тип истории |
| PRI | Предложенный приоритет решения |
| FILE | Индивидуальная запись пофайлового каталога |

У языковых документов разные технические ID и общий `entity_id`. Предметные CAN/CHAR/ARC не раздваиваются. Пути `.en.md` ведут к английской редакции; обе редакции ссылаются друг на друга.

## Что пока требует работы

Творческие вопросы остаются открытыми по своим исходным статусам. Переводы старых организационных файлов вне SPOT отмечаются как наследуемый языковой долг. Новое правило каталогизации пока закреплено нормативно; отдельной автоматической защиты от пропущенного файла нет.
