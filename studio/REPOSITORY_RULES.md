# Правила репозитория

Структура задаётся [structure.json](structure.json). У каждой предметной области три постоянных статуса, у каждого каталога — README с назначением. Постоянные инструкции, инструменты, шаблоны и реестры имеют одну действующую версию; Git хранит их историю. Их не нужно размножать в три конкурирующие копии.

## Что сохраняем

- Пути зарегистрированных областей, имена статусов и служебные каталоги.
- README каждой папки, AGENTS.md, условия прав, проверки и CODEOWNERS.
- Источники и статусы утверждений; устойчивые идентификаторы не переиспользуются.
- Отвергнутые и заменённые материалы с причиной, вместо удаления «для порядка».
- Работу другого автора: без force push, reset, массовых переносов или форматирования вне задачи.

## Входящие творческие материалы

Разрозненные идеи, смешанные концепты и ссылки на референсы можно временно регистрировать в [studio/inbox](inbox/README.md), не создавая новые верхнеуровневые предметные области. После разбора профильные карточки связываются по ID с исходной записью; входящий материал сам по себе не является каноном. Для прав и бинарных ресурсов сохраняются действующие ограничения.

## Как расширять

Обычные новые файлы и небольшие подпапки внутри области разрешены в рамках задачи; новая подпапка получает README и сохраняет понятный статус. Для нового верхнего раздела, предметной области, изменения статусов или переноса зарегистрированного пути нужен отдельный план в `studio/migrations/`: цель, карта old → new, затронутые ссылки, сохранение истории, возврат и подтверждение авторов. Обновление manifest без такого плана недопустимо.

После появления большого программного проекта игру можно вынести в отдельный репозиторий. Решение фиксирует владельца, права, точный способ привязки к канону и перенос исходников. Сейчас движок, язык, монорепозиторий игры и сроки не выбраны.

## Языки документов

Русский и английский — два равноправных языка документации. Для каждого документа предусмотрены версии на обоих языках независимо от языка оригинала; существующий корпус переводится поэтапно. Подробные правила и открытые вопросы — в [языковой политике](LANGUAGE_POLICY.md).

## Форматы

Пути — короткая ASCII-латиница, нижний регистр и дефисы; служебные имена README.md/AGENTS.md/CODEOWNERS и принятые GitHub-файлы сохраняют свой регистр. Тексты — UTF-8/LF. Markdown — для редактируемых текстов, CSV/JSON — для реестров и метаданных, SVG — для редактируемых векторов. Экспорт PDF/DOCX не заменяет редактируемую исходную версию без отдельного решения.

Секреты, приватные договоры, адреса, персональные снимки и чужие материалы без разрешения не публикуются. Папка archive тоже публична. Крупные бинарные мастера хранятся по [правилам ресурсов](ASSET_WORKFLOW.md).

## Что проверяет автоматика

Валидатор проверяет структуру, обязательные файлы, README, метаданные, часть ссылок, состояния, паспорта бинарных ресурсов и допустимость структурных изменений относительно базы. Проверка не доказывает авторство, подлинность согласия, отсутствие любого секрета, качество сюжета или историческую достоверность. Эти пункты остаются предметом review.

CI сам по себе не запрещает прямой push. Реальный запрет слияния при красной проверке обеспечивается ruleset в GitHub. Фактическое состояние — [rollout](rollout/STATUS.md).
